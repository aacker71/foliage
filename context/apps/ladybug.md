# Cloud Ladybug and Scarlet naming boundary

## Status

Cloud-only Ladybug is the user requirement. Integrated Canopy contains a paired local assessment workspace and the bounded Fireworks transport; this is not a deployed multi-user cloud agent. The Leaf assistant executes locally and is labeled Photosynthesis despite retained Scarlet module/route names.

## Responsibility

Provide a contextual cloud agent for portfolio work and, where allowed, public reader interaction. Keep local Photosynthesis collection and cloud reasoning visibly distinct. Scarlet is a current individual-agent name; naming alone does not specify execution location.

## Runtime and interfaces

Jev is required for Scarlet's structured journey and curation decisions as well as for
Photosynthesis. Use the [shared Jev contract](../contracts/agents-and-evaluation.md#jev-decisions-shared-by-photosynthesis-and-scarlet--2026-09-23)
with the run's admitted context, separate owner/public-reader scopes and existing bounded
operations. Jev complements the conversational inference route; it neither replaces that
route nor grants new read, edit, notification or publication rights. This integration remains
required implementation scope, not a capability established by the local claim-check page.

The [agent contract](../contracts/agents-and-evaluation.md) binds each run to verified
identity, selected context, current grants, bounded tools, cancellation and truthful stream
states. Reuse the integrated Canopy assessment/inference and AG-UI contracts. Current local
`/scarlet/run` is not evidence of an accepted cloud service.

## Storage and access

Private context may cross only through an explicit reviewed transfer contract. Public reader context must come from admitted publications. Keep per-person and per-tenant conversation state isolated. No remote read of an arbitrary local path or automatic publication.

## Data flow and acceptance

Local selection or public artifact → authorized cloud request → bounded tools/inference → cited answer with limitations. A benign Fireworks/Kimi inference request returned HTTP 200 on 2026-09-15. Evidence-bearing cloud rehearsal, retention/residency approval and hosted conversation acceptance remain distinct gates. Current naming ecology remains a reference, not a deployment map.

## Ownership

[Canonical architecture](../architecture.md) identifies implementation status. Do not create
an application manifest or broaden a licensing boundary merely to make this planned entry
look implemented. Units [16](../specs/16-cloud-tools.md), [17](../specs/17-cloud-conversation.md)
and [18](../specs/18-scoped-agents.md) own cloud context, conversation and scoped governance.

## Scarlet as a portfolio design collaborator

Scarlet must support scoped portfolio and leaflet customization through the same operations
as the user's controls: bounded edit sets, live preview, undo and conflict handling. It has
no separate portfolio state or unrestricted code-injection path. Public readers cannot gain
owner editing authority through conversation. See the
[customization contract](../proposals/portfolio-harness.md#81-user-and-scarlet-customization--required-product-scope).
These tools remain required implementation scope.

## Journey collaboration — local paired installation

`/leaf/scarlet` now selects one canonical journey and its current cited Leaflets. The existing
authenticated loopback companion accepts `/connection/journey`; Canopy reuses the bounded
Fireworks transport and validates proposed claim IDs, exact citations and highlight IDs.
The model returns proposals only. Owner-reviewed multi-statement edits use the existing
locked portfolio editor; curation uses its existing revision-bound form. Conversation is
private runtime scratch state, capped at sixteen journeys/eight turns and two hours; it is
not a second work record and does not survive an app restart. Changed documents invalidate
apply proposals. Browser progress is an enhancement of native form submission.

The workspace also exposes the existing local collection scheduler and links to configured
hosted notification preferences. Scheduling collects private source drafts. Separate per-journey Auto-update permission now
allows the local coordinator to call Jev and this companion for private, history-retaining
statement maintenance. See [the bounded Leaf contract](leaf.md#permitted-private-journey-maintenance--2026-09-28).
It does not authorize publication. Email digests remain unimplemented.
This paired installation is not multi-user hosted Scarlet or streaming conversation acceptance.
