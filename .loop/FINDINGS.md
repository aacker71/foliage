# Foliage — findings ledger

**Every blocking defect an adversary found, and the test that stops it coming back.**

`.loop/STATUS.md` says what is done. This says what was *wrong*, and it exists because the two
questions have different lifetimes: a capability can go DONE while the class of bug that nearly
sank it is still unguarded. A finding leaves this file only when a test would fail without the fix.

## Why this is a separate file with its own gate

Three blocking defects were found in two runs on 2026-08-19. Every one was caught by something
trying to break the work rather than admire it, and every one had already been *documented* by the
code that carried it:

- `F-001`'s bypass was described in `cos.mjs`'s own header, under a heading arguing it was correct.
- `F-003` was labelled "KNOWN SEAM MISMATCH" in the function that shipped it.

**Documenting a defect is not fixing it, and a comment is not a gate.** So a finding here is not
closed by a paragraph. It is closed by a named test that fails when the fix is reverted — and
`node tools/loop/findings.mjs` refuses the claim if that test does not exist.

## Allocating an id — check the open pull requests, not just this file

`node tools/loop/findings.mjs` reads only the ledger on the CURRENT BRANCH, so an id already
claimed by an unmerged branch is invisible to it — and this has already been hit at scale.

**Recorded on 2026-09-04: six ids meant two different defects each.** PR **#22**
(branch `c1-export-site-row`, 2026-09-01) carries **F-028 through F-034**; this file carries
**F-028 through F-033**, written 2026-09-03 and 2026-09-04. They overlap on six:

*(The ids in that table are in backticks deliberately: `findings.mjs` matches any line beginning
`| F-<digits> |` as a LEDGER ROW, so an unquoted comparison table is parsed as six malformed
findings. The gate refused this file the first time this table was written — which is the parser
being exactly as strict as the ledger needs.)*

PR **#25** (`f029-published-voice`) also held F-029 in its branch name, title and commits.
**Nobody was careless.** Every author checked the highest id in the ledger on their own branch,
which is the only thing the tool could see.

**Nothing is renumbered unilaterally.** Those are other people's reviewed branches and these rows
are already merged; whoever lands each PR decides which side moves, and if it is this file's, every
reference moves with it — `docs/PRODUCT-ARCHITECTURE-SPEC.md` §12 cites F-029, and several rows
here cite each other by id.

`findings.mjs` now REFUSES a duplicate id when two of them meet in one tree, which is the moment it
still costs a merge conflict rather than a silent wrong answer. It cannot see an id reserved in an
unmerged branch; nothing reading one working tree can.

Recorded here rather than inside the F-029 row on purpose. An id-allocation convention is not a
defect: it has no fix to guard and no test that could close it, and putting it in a row would give
one `status` and one `guard` cell to two unrelated things — so `--select` would offer them as a
single unit of work that cannot be half-closed. **One row, one finding.**

**Reconciled 2026-09-07 while porting the useful remainder of PRs #22/#23.** The already

below, and its unoccupied F-034 is retained for the path-rule duplication. Its published

claim no longer describes the current renderer. Historical browser measurements in that

records the earlier allocation conflict, not a second set of live finding rows.

| `unguarded` | fixed but nothing stops it returning. A regression waiting to happen. |
| `wontfix` | a deliberate owner decision, with the reason in the row. |

## The rule this file exists to enforce

**A row in `.loop/STATUS.md` may not read `DONE` while any finding against it is `open` or
`unguarded`.** The loop's SELECT phase reads this file before the ledger: an `open` finding
outranks every status, because a known defect in shipped code is worth more attention than an
unstarted capability. `BROKEN > DARK > PARTIAL > TODO > BUILT` orders *work*; this orders *debt*,
and debt goes first.
